# 제슐렝가이드 요구사항 명세 (P0)

> jelin-guide-agent-design.md(이하 "설계서") **6장 인터뷰 확정 결정**에 기반한 P0 산출물.
> W1 워크플로우의 모든 후속 Phase가 본 문서를 기능적 입력으로 사용한다.
> 설계서와 충돌 시 본 문서 → 설계서 6장 → 1~5장 순으로 우선한다.
>
> - **작성일**: 2026-04-28
> - **의사결정자**: 운영자 1인 (단일 의사결정 구조)
> - **MVP 일정**: 1주 내 P9 도달 (P0 / P9만 명시 게이트)

## 1. 개요

### 1.1 목적
사내 구성원이 제로페이 가맹 맛집을 직접 추천·평가하는 모바일 웹. **익명성·간단함·게이미피케이션**을 핵심 가치로 한다. 외부 가맹점 API·크롤러 미사용, 사용자 직접 입력만이 데이터 출처다.

### 1.2 MVP 정의 (Definition of Done)
P9 통합 테스트·배포 완료 시점까지 다음 시나리오가 프로덕션에서 통과한다.

1. 비회원이 메인 화면에 진입해 가맹점 리스트·지도·랭킹을 열람한다.
2. 신규 사용자가 닉네임/비번으로 가입한다.
3. 가맹점을 제안한다 (주소 입력 → 자동 좌표 변환 → 카테고리 선택 → 제로페이 여부 체크 → 저장).
4. 등록된 가맹점에 3차원 5점 리뷰를 쓴다.
5. 카테고리·평점 필터로 검색·정렬한다.
6. 지도에서 마커를 클릭해 상세로 이동한다.
7. 마이페이지에서 자신의 제안·리뷰·랭킹 위치를 확인한다.
8. 잘못된 가맹점 정보를 수정하고, 이력에서 롤백한다.
9. 운영자가 `/admin`에서 신고를 검토하고 시드 가맹점을 추가한다.

## 4. 기능 명세

각 기능은 **우선순위 / 관련 Phase / 수용 기준(체크리스트)** 을 갖는다. 체크리스트의 모든 항목이 P\* 종료 시점에 통과해야 해당 Phase의 성공 기준이 충족된 것으로 간주한다.

### F1. 인증 — 가입·로그인·세션·탈퇴
- **우선순위**: Must / **Phase**: P3
- **수용 기준**
  - [ ] 닉네임(2~16자, 한글·영문·숫자·`_` 허용)과 비밀번호(8자 이상)로 가입 가능.
  - [ ] 닉네임 중복 시 `X_2`, `X_3` 접미사를 서버가 첫 미사용 후보로 자동 추천.
  - [ ] 가입 화면에 "복구 수단 없음 — 자주 쓰는 기기에 저장 권장" 경고 명시 표시.
  - [ ] 로그인 성공 → DB 세션 발행 (httpOnly 쿠키, SameSite=Lax, 만료 30일).
  - [ ] 로그아웃 → DB 세션 즉시 삭제, 쿠키 제거.
  - [ ] 탈퇴 → 계정만 삭제, 작성한 제안·리뷰는 **원 닉네임 그대로 잔존**. 사전 경고 모달 노출.
  - [ ] 비밀번호 평문 저장 0건 (bcrypt round ≥ 10).
  - [ ] 동일 IP / 동일 닉네임 로그인 실패 5회 시 짧은 딜레이 — *추후 결정* 가능, MVP에선 미적용도 허용.

### F2. 가맹점 제안
- **우선순위**: Must / **Phase**: P4
- **수용 기준**
  - [ ] 필수 입력: 상호, 주소, 카테고리(고정 enum 8종), 제로페이 여부.
  - [ ] 선택 입력: 대표 메뉴, 가격대 (텍스트 메모 1~2칸).
  - [ ] 주소 입력 → 서버 프록시로 네이버 Geocoding API 호출 → 좌표 자동 변환.
  - [ ] Geocoding 실패·복수 결과 → "주소를 다시 확인해주세요" 메시지 + 재입력 유도. 수동 좌표 입력 미지원.
  - [ ] 중복 감지: 좌표 50m 이내 + 상호 유사도 ≥ 0.8 → 자동 차단, "이미 등록된 가게입니다. 리뷰로 가시겠어요?" CTA로 기존 상세로 유도.
  - [ ] 제안 성공 → 마이페이지의 "내가 제안한 가맹점" 목록에 즉시 노출, 제안 랭킹에 가산.
  - [ ] 비로그인 상태에서 제안 시도 → 로그인/가입 모달 후 원 흐름 복귀.

### F3. 가맹점 위키식 수정·롤백
- **우선순위**: Should / **Phase**: P4 (서버), P5 (UI)
- **수용 기준**
  - [ ] 로그인한 사용자는 누구나 가맹점 모든 필드를 수정 가능.
  - [ ] 수정 시 `PlaceRevision` 레코드 누적 저장 (변경 전/후 스냅샷, 작성자, 시각).
  - [ ] 가맹점 상세에 "수정 이력" 진입 버튼.
  - [ ] 수정 이력 페이지 — 각 버전마다 "이 버전으로 되돌리기" 버튼 (롤백은 새 리비전을 만드는 형태, 데이터 손실 없음).
  - [ ] 좌표 변경 시 Geocoding 재호출 — *결정값* P4. 결과 미스매치 시 사용자 확인 단계.

### F4. 리뷰 — 작성·수정·삭제
- **우선순위**: Must / **Phase**: P4 (CRUD), P5 (UI)
- **수용 기준**
  - [ ] 평점 3차원(맛 / 가성비 / 분위기) 각 1~5점 필수.
  - [ ] 본문 텍스트 (최소 10자, 최대 1000자).
  - [ ] 동일 가맹점에 동일 사용자는 1개의 리뷰만 — 재작성은 수정 흐름.
  - [ ] 작성자는 언제든 수정·삭제 가능. 수정 라벨 미부착(이력 비공개).
  - [ ] 삭제 시 다음 랭킹 캐시 주기에 재계산 반영.
  - [ ] 가맹점 상세에 차원별 평균 + 단순 평균 표시.

### F5. 검색·필터·정렬
- **우선순위**: Must / **Phase**: P8
- **수용 기준**
  - [ ] 텍스트 검색 — 상호·메뉴 메모 부분 일치 (대소문자·공백 무시).
  - [ ] 카테고리 필터 (multi-select): 한식 / 양식 / 일식 / 중식 / 분식 / 카페 / 주점 / 기타.
  - [ ] 평점 필터: 평균 4.0 이상, 4.5 이상.
  - [ ] 리뷰 수 필터: 1+, 5+, 10+.
  - [ ] 정렬: 인기순(평점·리뷰수 가중), 최신순, 거리순(위치 권한 허용 시).
  - [ ] URL 파라미터로 모든 필터 상태 반영 → 공유 시 동일 결과 재현 가능.
  - [ ] UI: 상단 스크롤 칩 + 별도 "필터" 버튼 → Bottom Sheet 고급 필터.
  - [ ] 모바일 무한 스크롤 / PC·태블릿 페이지 번호 (하이브리드 페이지네이션).

### F6. 지도 통합
- **우선순위**: Must / **Phase**: P6
- **수용 기준**
  - [ ] 네이버 지도 SDK 로드 (클라이언트 키는 환경변수, Geocoding은 서버 키 분리).
  - [ ] 마커 50개 이상 시 자동 클러스터링 (네이버 SDK MarkerClustering), 줌 인 시 해제.
  - [ ] 마커 클릭 → 가맹점 미리보기 카드 (상호·평점·리뷰 수·상세 진입 버튼).
  - [ ] 필터 적용 시 마커·하단 리스트 동기 갱신.
  - [ ] 모바일 줌·드래그 정상 작동 (네이버 SDK 기본).
  - [ ] 지도 영역(viewport) 변경 → 리스트 결과도 같이 갱신.

### F7. 랭킹
- **우선순위**: Must / **Phase**: P7
- **수용 기준**
  - [ ] **제안 랭킹**: 누적 제안 수(중복 차단 후) 단일 — 전체 기간.
  - [ ] **이달의 심사위원**: 이번 달 작성된 활성 리뷰 수 기반 가중 — 매일 자정 KST 기준 집계.
  - [ ] **명예의 전당**: 누적 활성 리뷰 수 기반 가중 — 전체 기간.
  - [ ] 두 보드는 화면에서 시각적으로 분리 (탭 또는 위·아래 분리).
  - [ ] 동일 입력 → 동일 결과 (deterministic).
  - [ ] 캐시 주기 *추후 결정* (P7 가설치: 5분).
  - [ ] 리뷰 삭제·수정·탈퇴(닉네임은 잔존하나 활성 사용자 카운트 별도) 시 다음 캐시 주기에 반영.
  - [ ] 랭킹 공식·가중치는 `/output/specs/ranking-formula.md`에 정식 기록.

### F8. 마이페이지
- **우선순위**: Must / **Phase**: P5 (구조), P7 (랭킹 결합)
- **수용 기준**
  - [ ] 내가 제안한 가맹점 목록 — 각 항목에서 가맹점 수정 진입.
  - [ ] 내가 쓴 리뷰 목록 — 각 항목에서 수정·삭제 진입.
  - [ ] 내 랭킹 위치 — 제안 / 이달의 심사위원 / 명예의 전당 각 N위 표시.
  - [ ] 추이 그래프 (4주 누적 카운트) — *Should*, MVP 후순위로 비움 가능.
  - [ ] 설정 — 닉네임 접미사 변경, 비밀번호 변경, 탈퇴.

### F9. 신고·자동 숨김
- **우선순위**: Should / **Phase**: P4 (서버), P5 (UI), P9 (어드민)
- **수용 기준**
  - [ ] 모든 리뷰·가맹점에 신고 버튼 (로그인 필요).
  - [ ] 동일 사용자 → 동일 항목 신고 1회 제한.
  - [ ] 누적 신고 ≥ 3건 → 항목 자동 숨김 상태로 전환 (운영자 검토 대기).
  - [ ] 숨김 항목은 비로그인·일반 사용자에게 비노출. 작성자에게는 "신고 누적으로 검토 중" 표시.
  - [ ] `/admin`에서 복원 / 영구 삭제 결정 → 즉시 반영.

### F10. 제로페이 자가신고 + 사용자 투표
- **우선순위**: Should / **Phase**: P4
- **수용 기준**
  - [ ] 가맹점 등록·수정 시 제출자가 "제로페이 사용 가능 / 불가" 자가신고.
  - [ ] 다른 사용자도 같은 가맹점에 "사용 가능 / 불가" 투표 가능 (1인 1표, 변경 가능).
  - [ ] 가맹점 카드·상세에 다수결 결과 표시 — 동수·미확인 시 "주장·미확인" 라벨.
  - [ ] 표 분포(예: 8 / 10) 상세 페이지에 노출.
  - [ ] 외부 제로페이 API 미사용.

### F11. 관리자 페이지 (/admin)
- **우선순위**: Must (운영 필수) / **Phase**: P9 직전 보강
- **수용 기준**
  - [ ] `/admin` 라우트 — Basic Auth (`BASIC_AUTH_USER` / `BASIC_AUTH_PASS` 환경변수) 1단계 보호.
  - [ ] 신고 대시보드 — 임계 도달 항목 리스트, 복원·삭제 버튼.
  - [ ] 탈퇴 처리 — 잔존 정책(닉네임 유지) 확인 UI.
  - [ ] 시드 가맹점 추가 — 일반 제안 흐름과 동일하지만 운영자 식별 닉으로 표시.
  - [ ] 수정 이력 조회·롤백.
  - [ ] 환경변수 누락 시 명확한 503 메시지 (서비스 자체는 동작).

### F12. 시드 데이터 주입
- **우선순위**: Must / **Phase**: P9 직전 (운영자 작업)
- **수용 기준**
  - [ ] 운영자 전용 닉(예: `제슐렝가이드_운영팀`)으로 시드 5~10개 등록.
  - [ ] 시드 가맹점은 일반 사용자 흐름과 동일한 제약(중복 차단·Geocoding) 통과.
  - [ ] 부트스트랩 모드 분기 임계: 가맹점 < 5건 또는 리뷰 < 10건일 때 홈을 "첫 제안자가 되어보세요" CTA로 전환.
  - [ ] 시드 등록 후 임계를 넘으면 부트스트랩 모드 자동 해제, 정상 큐레이션 카드 홈으로 전환.

### F13. 모니터링·로깅
- **우선순위**: Could / **Phase**: P9
- **수용 기준**
  - [ ] Sentry 연동 — 서버·클라이언트 에러 자동 보고. PII 미수집 (닉네임만 허용, 비번·세션 토큰 미전송).
  - [ ] Netlify Analytics 활성화.
  - [ ] PostHog·Plausible은 미도입.
  - [ ] `/output/reports/deployment-{date}.md`에 배포 직후 스모크 결과·환경변수 점검 기록.

### F14. 비회원 열람
- **우선순위**: Must / **Phase**: P3·P4·P5 전체
- **수용 기준**
  - [ ] 가맹점 리스트·상세·지도·랭킹·다른 사용자 프로필 페이지 모두 비로그인 열람 가능.
  - [ ] 쓰기·수정·삭제·신고·투표·탈퇴 모든 동작은 로그인 미들웨어로 보호.
  - [ ] 비로그인 상태에서 쓰기 버튼 클릭 → 로그인/가입 모달 노출 후 성공 시 원 화면으로 복귀.

## 5. 비기능 요구사항 (NFR)

| 분류 | 요구 | 측정 방법 |
|---|---|---|
| 성능 | 모바일 첫 페인트 < 2.5s (3G 가정), 랭킹 API p95 < 500ms (시드 데이터 기준) | Lighthouse / 단위 측정 |
